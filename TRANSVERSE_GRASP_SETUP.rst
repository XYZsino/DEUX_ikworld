90도 봉투 전용 파지
===================

사용자 확인: +90도와 -90도 모두 포함하며, 봉투의 긴 축을 유지하면 앞뒤180도
반전은 허용한다. 이 경우에 한해 원래 기준 파지 자세의 전체30도 제한을 벗어난다.

분기와 각도 유지
----------------

* 관측 yaw가 +60..+120도 또는 -120..-60도면 전용 경로만 선택한다(양 끝 포함).
* +60..+120도는 손의 수평 방향을180도 뒤집은 -120..-60도로 대응시킨다.
* 전용 저장 자세는 -120..-60도를5도 간격으로 탐색했다. 입력 yaw와 저장 축의
  차이2.5도 이하, 저장 경로의 축 유지 오차0.5도 이하로 총3도 예산을 둔다.
* 같은 준비자세에서 시작해 상부8cm까지 자세를 맞추고, 하강·접촉·상승·정지 동안
  그 회전을 유지한다. 준비자세→상부 전환도3초 접촉 경로에 포함한다.
* 각도를 유지할 검증 경로가 없으면 대기한다. 일반 경로로 대체하지 않는다.
* 나머지 yaw에서는 기존 XY 우선/회전 보조 선택을 그대로 사용한다.
* X 오차3cm, ETA3.8..10초, Z=0.97m, 속도(0,-0.09,0)m/s는 유지한다.
  닫힘2.5..3초, 접촉/상승 시작3초, 상승 완료4.5초, 정지5초다.
* 전송 전 최신 XY·ID·방향 분류·축 오차를 확인한다. 전송 후에는 경로·각도·시각을
  고정하고 인식 변화는 로그로만 기록한다. 비상정지/명시적 취소는 유지한다.

탐색 결과(실기 파지 검증 아님)
------------------------------

전용590개 궤적 / 74개 XY 위치. 정확히90도에 대한 저장 X 격자는
0.51,0.54,0.57,0.60,0.63,0.66,0.69,0.72m에서 확보했다.
60..120도 전체 각도 격자의 후보가 있는 X는0.54..0.66m다.
각 X/각도에서 가능한 접촉 Y는 서로 다르므로 단일 사각형 작업공간을 뜻하지 않는다.
그 밖의 X 또는 각도에서의 실패는 유한 IK/경로 탐색의 실패이지 도달불가 증명이 아니다.

artifacts/right_grasp_transverse_search/poses_by_x.json: 90도 대표 준비/접촉/정지 관절 자세.
summary.json: X별 가능한 각도와 Y 위치 수, 독립 검증 결과.
x_angle_coverage.png: X-각도별 가능한 접촉 Y 개수 지도.
trajectories/: 자세 유지와 시간 조건을 통과한 전체 저장 궤적.

시작
----

다른 /task/grid_grasp 실행기는 종료한 뒤 사용한다. 새 통합 라이브러리에는
일반1,587개와 전용590개 경로를 함께 저장하지만 선택 분기는 서로 분리한다.
현재 고정 왼팔로 먼저 재검사한다(명령 발행 없음)::

  source setup_env.bash
  ROS_DOMAIN_ID=12 python tools/audit_rotation_grid_left.py \
    --library-directory "$PWD/artifacts/right_grasp_grid_classified" \
    --output-directory "$PWD/.setup/grid-grasp-classified-test"

미리보기(기본값, 팔/손 명령 없음)::

  bash run_rotation_grasp_trial.bash

별도 실제 실행 요청이 있을 때만::

  bash run_rotation_grasp_trial.bash --ros-args -p enable_execution:=true
  ros2 action send_goal /task/grid_grasp deux_task_msgs/action/MoveToReady '{}' --feedback

실제 준비자세 이동은 자동 수행하지 않는다. 기존 손 닫힘/상승 상태도 바꾸지 않는다.
일반 경로만 쓰던 이전 launcher는 run_normal_rotation_grasp_trial.bash에 보존했다.

범위
----

실측 URDF/설치 YAML/관측 표면과 기존 충돌 모델을 사용한 소프트웨어 검증이다.
전체 몸통·자기충돌·숨은 설비·파지 물체 형상, 토크·하중 및 실제 파지 성공은 미검증이다.
실기 프로세스에 적용해도 하드웨어 모드/준비자세 검사와 별도 Action 요청이 필요하다.

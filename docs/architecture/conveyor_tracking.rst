이동 컨베이어 추종 구현과 검증 범위
=================================

속도는 사용자 확인8cm/s입니다. sim은 -Y 방향0.08m/s로 계속 이동하며,
준비·인식·파지 중 컨베이어를 정지시키지 않습니다. 실제 이동 방향은 별도 측정해야
합니다. 작업 시작 전 상자와 물체를 상류에 배치하는 설정만 사용하며 실행 중
물체 위치를 덮어쓰거나 weld로 손에 고정하지 않습니다.

준비 자세
---------

URDF 관절0 → 후퇴 위치에서 EE XY를 유지하는 팔꿈치 굽힘 경유점 → 원래
운용 준비자세 순서입니다. 최신 head_calibration.yaml은 이 기준에서 오른손
EE를 약73.6mm 낮추고 X+74.1mm/Y+149.8mm로 파지 영역에 가까이 배치하며
손가락을 미리 연 자세입니다. 손목 방향 변화는약0.30°입니다. 원래 기준값은 ready_pose.HOME_JOINTS에
보존합니다. 상세 수치와 검증은 low_ready_intercept.rst를 참고하십시오.

관측과 파지 조건
---------------

ZED 2i RGB-D → YOLO11n-seg/ByteTrack → 선택 ID의 masked-depth ICP →
취득시각 기준 XYZ/yaw 및 속도 Kalman → BT 진입 판단 → TrackGrasp 계획입니다.
기존 정지 물체용15초 pose 고정은 이동 모드에서 사용하지 않습니다.

필터는 관측이8cm 이상 튀거나 yaw 변화0.5rad를 넘거나 innovation/speed 조건을
벗어나면 거부합니다. 거부값은 마지막 정상 관측의 시각을 갱신하지 않습니다.
중복/역순 입력도 거부하며0.6초 이상 관측 공백 후에는 속도를 새로 추정합니다.
가속도 노이즈 표준편차는 기본0.015m/s²로 분리했습니다. 이 값은 정상 속도
컨베이어용 sim 설정이며 실제 가감속·깊이 노이즈에 맞는 검증이 필요합니다.

선택 영역과 파지 시도 영역을 분리했습니다. base_link 기준 metre 단위로:

* 추적 시작 영역: [0.45,-0.48,0.68] ~ [0.60,0.40,0.82].
* 파지 시도 영역: [0.45,-0.48,0.68] ~ [0.60,0.12,0.82].

상류에서 먼저 추적하고 최소6개 필터 관측, 최근3개 속도 추정 간 차이
0.004m/s 이하를 확인합니다. 현재 포즈가 상류 추적 영역에 있고 예상 도착 및 닫힘 위치가 파지 영역의
내부 여유15mm를 유지할 때 접근합니다. 실제 TrackGrasp 시작은 새 관측이
파지 영역 안에 있어야 합니다. 실행 시각/동적 제한에 맞춰 다시 검증합니다.
이 직육면체는 sim용 후보 영역이며 모든 점의 실기 도달성 보증이 아닙니다.
실제 계획은 별도로 IK·관절 속도/가속도·설비 충돌 검사를 통과해야 합니다.

동작과 중단
-----------

Approach는 취득 시각부터 예약 시작과 이동 시간을 반영해 미래 위치의 위쪽으로
접근합니다. 도착 이후 촬영된 새 ICP/Kalman 관측을 기다린 뒤 TrackGrasp를
새로 계획합니다. TrackGrasp는 Track→Descend→Close의 연속 궤적입니다.
Track은 새 포즈의 이동 속도에 맞추고, 이후 하강과 손 닫힘을 이어갑니다.
arm/hand bridge는 예약 시각에 동기화합니다. 동적 제한을 초과하면 해당 단계의
시간만 늘리고 미래 위치/작업 영역을 다시 검사합니다. 허용 속도/가속도는
늘리지 않습니다. 닫힘 마지막에는 제한된 감속을 적용합니다.

실행 중 최신 filtered pose를 같은 시각의 계획 예측과 비교합니다. 최신 구현의
열린 손 Track 구간에만 불확실성을 계산한 최대0.8초 예측 예외가 있으며,
하강/닫힘에는 신선한 관측을 요구합니다. low_ready_intercept.rst가 최신 기준입니다.
위치 편차25mm 초과, 방향 편차, 관측 만료, 영역 이탈 등은 중단합니다.
이는 관측으로 감시하는 예측 궤적입니다. 실행 중 매 영상마다 관절 목표를
덮어쓰는 visual servo나 자동 재계획은 아직 구현하지 않았습니다.
중단 후 무조건 다시 닫거나 계속 이동하지 않습니다.

현재 hand_open/hand_closed의 오른손 엄지 첫 관절 목표는 -0.02rad입니다.
상한0rad에 직접 명령하던 값에서 여유를 둔 sim 파지 설정입니다.
bridge/URDF 관절 제한과 감시 오차는 늘리지 않았고 HOME 준비자세는 바꾸지
않았습니다. 파지 후에는 ICP 지원면 가정을 종료하고 영상의 손 근처 봉투와
바코드 검증으로 전환합니다. 실제 접촉력/파지 성공을 영상만으로 보증하지 않습니다.

구현 위치
---------

* core/motion_filter.py: Kalman 및 급변값 거부.
* perception/icp_node.py: 선택 ID/요청별 필터 적용과 원 취득시각 유지.
* runtime/head_task_node.py: 상류 선택·안정화·진입 조건·BT.
* core/conveyor.py: 미래 파지 위치와 연속 경로.
* runtime/motion_planner_node.py 및 execution_node.py: 예약 실행·최신 관측 감시.
* sim/head_calibration.yaml: 영역·예측시간·준비/파지 설정.

실기 전에는 카메라 외부 보정, 작업 공간, 컨베이어 방향/가감속, 모터 응답,
접촉에 따른 추정 편향과 가림, 정지 거리, 파지 실패 복구를 검증해야 합니다.

최신 검증 결과
-------------

``validation/head-rgbd/zed-moving-07``은 ZED 영상으로 준비→속도추정→접근→
하강→닫힘까지 진행했습니다.11.220초에 위치 예측 편차 감시로 중단했습니다.
오프라인 저장 물리 상태와 비교하면 가림이 커질 때 filtered ICP의 Y 편향이
약19.4mm까지 누적됩니다. 전체 이동 파지의 정상 동작/성공은 아직 미검증입니다.
이 시험의 설비/물체 침투0, 물리경고0, weld0이며 준비팔 오차는0.0006494rad입니다.
88개 회귀시험 및8개 ROS 패키지 빌드는 통과했습니다.

기록: ``dashboard-rgbd.html``, ``scenario-rgbd.mp4``, ``integration-audit.json``.
``pose-audit.json``은 저장된 물리 상태의 사후 비교이며 제어 입력으로 사용하지
않았습니다. 부분가림에서의 ICP 편향, 관측 불확실성 처리, 재계획이 남아 있습니다.


접근 진입 예측 시간과 관제 사유 (2026-10-27)
--------------------------------------------

EstimatePose의 고정 entry_lookahead=7초 조건을 제거했다. 진입 전 예상 파지 완료까지는
start_lead + Approach + intercept_wait_s + start_lead + Track + Descend + Close를
사용한다. Approach와 TrackGrasp가 각각 별도 Action이므로 시작 여유를 두 번 포함한다.
현재 설정은0.4+1.5+1.0+0.4+0+0.8+1.0=5.1초이다. 영상 취득 후 경과 시간도 더한다.
하강 중 손가락 닫기 overlap은 닫힘 시작을 당길 뿐 기존 궤적 완료시각을 줄이지 않으므로
이 계산에서 중복 차감하지 않는다. 두 예측 위치에는 기존 파지 영역 경계 여유를 적용한다.
예측 속도는 모션 플래너와 같은 검증된 conveyor_velocity를 사용한다.

이 값은 계획 생성 전 모션 설정 기반 예상 시간이다. 실제 IK·관절 제한에 따른 재시간화는
이후 plan_conveyor/plan_track_grasp에서 수행하며, 실제 궤적 시간으로 파지 영역 이탈과
max_plan_horizon을 다시 검사한다. 미래 플래너 계산/피드백 지연을 정확히 아는 값은 아니다.
기존 설정 파일에 entry_lookahead가 남아 있어도 사용하지 않는다.

TaskStatus.reason에 ICP 요청 결과 대기, 선택 ID 포즈 결손/노후화, 필터·속도 유효성,
관측 횟수, 속도 안정성, 현재/예측 영역 이탈을 구분해 표시한다.
예측 이탈은 관측 기준 예측 시간, XYZ 좌표, 남은 예상 동작 시간을 포함한다.
통과하면 사유를 지우고, 시간 초과하면 마지막 불충족 사유를 종료 결과에 보존한다.
GUI는 현재 단계 아래에 이 사유를 표시하며 중복된 종료 메시지는 한 번만 표시한다.


TrackAndSelect 상세 사유 (2026-10-27)
------------------------------------

TaskStatus.reason에 검출·추적 입력 대기/시각 불충족, 봉투 미검출, 지정 ID 미검출,
신뢰도 부족, 추적 ID 미발급, 3D 후보 수신/요청 일치/시각 불충족을 구분한다.
영상 ID에 대응하는 후보가 없거나, 봉투 가시성·깊이 좌표·선택 영역 조건을 만족하지
못하면 각 사유별 후보 개수를 표시한다. 영역 밖 후보의 예시 XYZ와 허용 범위를 cm로
표시한다. 유효 후보는 서로 다른 영상 취득 시각 기준 관측 횟수를 n/3회로 표시한다.
상류 우선 및 지정 ID 선택, 선택 영역,8초 제한은 유지한다.
선택 성공 시 사유를 지우고, 시간 초과 시 마지막 사유를 종료 결과에 보존한다.

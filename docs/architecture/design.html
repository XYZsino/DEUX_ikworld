기존 DEUX 위에 추가하는 파지·스캔·적재 태스크

기존 드라이버와 ROS 2 제어 인터페이스는 그대로 사용하고, 별도 overlay workspace에 7개 제어·연동 노드 + 1개 작업 공간 설정 노드를 추가합니다. 시뮬레이션의 BT·파지 계산·Hermite 경로를 라이브러리로 가져오되, 실기 관측 수신과 시간 기반 실행은 새 노드가 담당합니다.

전체 구조도 열기 → · 구조도는 archify로 작성했습니다. 설명은 한국어이며 고정 Viewer UI와 HTML 언어 속성은 도구 지원에 따라 영어입니다.

이번 작업은 구조 설계입니다. /home/xyz-ai/git/DEUX의 코드·설정은 수정하지 않았습니다. 상위 외부 카메라에서 ICP pose를 로봇 베이스 좌표계로 전달한다는 최신 조건을 사용합니다. 기존 head camera를 필수 입력으로 요구하지 않습니다.

4. 현재 시나리오의 실행 순서

대상 관측추적·접근하강·파지수직 상승·검증전방 스캔양팔 동시 이동놓기·검증복귀
  1. 시작: 로봇·손 측정 상태와 설치 설정을 읽고 시작 자세를 측정값으로 맞춥니다. 카메라 pose가 들어오기 전 물체 위치를 미리 알지 않습니다.
  2. 파지: 봉투 pose와 손가락 접점을 기준으로 접근 자세/깊이를 계산합니다. 손 관절 잔차는 접촉 가설이며, 상승 후 실제 물체 이동을 함께 확인합니다.
  3. 스캔: 오른팔 전방으로 뻗는 자세를 기본으로 양면의 낮은 좌측 스티커 중 접근 가능한 면을 선택합니다. 왼손 리더가 추종하고 새 판독 문자열이 들어와야 성공입니다.
  4. 적재: 스캔 전 자세로 역재생하지 않습니다. 왼손 리더 후퇴와 오른팔 적재 이동을 동시에 계획합니다. 직접 경로가 가능하면 사용하고, 불가하면 검증된 안전 경유점을 Hermite로 연속 통과합니다. 현재 seed1 성공은 경유점1개였으며 모든 설치에서 직접 경로를 보장하지 않습니다.
  5. 검증/실패: 놓은 위치·손과의 분리 확인 후 성공. BT는 실패 원인을 받아 정지/복구합니다. 기존 관측 제어기에는 스캔 최대3회가 있으나, 이전 별도 시나리오의 파지 최대2회 재시도는 이 제어기로 아직 이식되지 않았습니다. 신규 BT에서 최초 포함 파지2회/스캔3회를 명시하고 동일 대상·새 관측·재접근 여유가 있을 때만 재시도하도록 구현할 항목입니다.

5. sim 코드를 그대로 실행하기 전에 필요한 경계 변경

현재 상태 / 문제설계에서의 처리
ControlIO.step 안에서 controller.tick과 계획이 동기 실행. 명령 유효시간 기본0.1s.계획 worker와 실행 루프 분리. 느린 계획 뒤 이미 만료한 명령을 전송하지 않음. 수락 시 로봇 시작 자세·대상 이동·scene 버전을 재검증. 관측 기반 추종도 준비된 다음 구간만 연결.
일부 코드가 매 tick마다 다음 궤적 sample을 소비.실기 측정 시계/실행 elapsed time 기준 샘플링으로 변경. callback 누락/지연 때문에 궤적이 느려지거나 순간 점프하지 않도록 재타이밍. Hermite 통과 속도를 단일점 목표 반복으로 없애지 않음.
tracker max_age=.3s, 현재 관측 포맷에 개별 pose 촬영시각/품질 축 정보 부족.개별 촬영 시각·지연·공분산을 새 메시지에 포함. 추적 예측은 유효시간/불확실도 상한 안에서만 사용. 단순 timeout 확대 대신 실제 ICP 지연 분포로 조정.
ICP가 테이블 위 XYZ+yaw만 추정하면 들어 올린 봉투의 tilt를 설명하지 못함.지지 상태와 파지 후 추적 모드를 분리. 파지 후 6D 추정 또는 이미지/라벨 depth·손 상대 pose 기반 보조 관측 필요. EE만으로 만든 예측을 파지 성공의 독립 증거로 세지 않음.
sim 관절 모델·고정 lift·EE grasp site와 실기 URDF 원점이 같다는 보장 없음.실기 robot_description과 고정/측정 lift, EE→접점, 손목→리더를 설치 설정으로 사용. 팔 명칭은 같아도 FK·관절 부호·영점·범위 비교 필수. 현재 sim 6N을 goal_current에 숫자6으로 넣지 않음.
현재 모델에 정적 물체/충돌 템플릿과 MuJoCo 계산이 포함.MuJoCo는 IK/FK·기하 계산용 라이브러리로 유지 가능. live sim adapter의 정답 pose·접촉력·컨베이어 상태는 실기 입력에 포함하지 않음. 실제 상태는 센서/로봇 피드백만 사용.

6. 컨베이어 높이·위치가 바뀌는 경우

봉투 pose가 base 기준으로 주어지면 접근 목표는 관측에서 다시 계산할 수 있습니다. 출발 박스 높이 7cm와 정적 봉투 형상으로 지지 높이/상승 여유를 추정하되, 봉투 하나만으로 박스 벽의 XY 위치·컨베이어 전체 윤곽·적재함 위치까지 알 수는 없습니다.

  • installation.yaml: destination pose/내부 크기, conveyor plane/작업 영역, box height=.07, lift 상태, reader·EE 보정. 기존 소스 수정 없이 설치별 값 교체.
  • 초기에는 출발 박스 벽/컨베이어 경계를 보수적 설정으로 제공하고, 추후 RGB-D 평면/박스 검출로 scene을 갱신합니다. 관측 없이 설치값이 자동 보정된다고 표시하지 않습니다.
  • 기존 스캔 위치·팔꿈치 자세·경유점은 선호 경로로 사용합니다. IK 불가하면 위치/자세 후보를 재탐색하되 관절 한계·충돌·탑재 봉투 여유·실제 판독 성공은 유지합니다.
  • 새 카메라 외부 파라미터는 추후 URDF 반영 전까지 별도 설정/정적 TF로 제공할 수 있습니다. pose가 이미 base 기준이면 제어를 위해 head cam 보정을 강제하지 않습니다.

7. 기존 코드 수정 없이 배치

deux_task_ws/                  # 새 overlay, DEUX 원본은 그대로
  src/
    deux_task_msgs/            # 관측·계획·실행 메시지/Action
    deux_task_core/            # sim 제어 로직을 이식한 비ROS 라이브러리
    deux_task_perception/      # observation_node, barcode_bridge_node
    deux_task_runtime/         # scene_node, task_node, planner, execution
    deux_task_adapters/        # arm_bridge_node, hand_bridge_node
    deux_task_bringup/

      config/installation.yaml
      config/hand_mapping.yaml
      config/task.yaml

기존 DEUX install을 underlay로 source하고 새 workspace를 build합니다. 기존 bringup launch를 포함하거나 이미 실행된 드라이버에 연결합니다. 기존 controller_manager를 중복 생성하지 않습니다. 태스크는 양팔·손만 제어하며 모바일/리프트는 작업 중 고정합니다.

명령 충돌: 기존 teleop와 state_node도 팔 궤적 토픽에 직접 쓰므로 새 execution_node 하나로 기존 발행자를 강제 중재할 수 없습니다. 자동 작업에서는 teleop를 시작하지 않고 state 모드 전환을 비활성화하거나, 별도 launch의 remapping으로 기존 명령을 격리해야 합니다. 소스 수정 없이 가능하지만 실행 구성은 구분해야 합니다. /state/status 감시와 경쟁 publisher 검사는 보조 검사이며 ROS Action client 경쟁까지 완전한 lock으로 보장하지 않습니다.

8. 구현 순서와 완료 기준

  1. 관측/손 매핑 확정: 손 측정 토픽·모터ID·임의 rad 명령 지원·전류 단위, 바코드 연결 방식 확인. 관절 name/순서 및 base/EE FK 대조. 누락 피드백 상태에서 실행 거부.
  2. 드라이런: rosbag 관측 재생 → BT/계획기 → 출력 기록만 수행. 명령 전송 없이 상태·목표·시각·만료·IK 횟수를 sim 결과와 비교.
  3. fake hardware: 기존 use_fake_hardware:=true를 사용해 팔 Action 연동 검증. 손은 별도 fake adapter 필요. cancel, deadline, 시작 자세 불일치, 경쟁 명령, 피드백 끊김을 검증.
  4. MuJoCo ROS 어댑터: 동일 신규 ROS 노드에 sim 입력/출력을 연결해 파지·스캔·적재와 실패 재시도 비교. fake hardware만으로 접촉/파지 성공을 검증하지 않음.
  5. 현장 검증: 정지 물체·짧은 단계부터 확인하고 컨베이어 이동/위치·높이 변화로 확대. 성공률, 손 미끄러짐, fresh barcode, 적재 확인, 팔/손 동기 오차를 기록.

SIM 파지 후보 비교와 Lift 사전 검증
===================================

2026-10-27. head_calibration.yaml의 conveyor_tracking.candidate_search로 활성화한다.
실기 설정에는 자동 적용하지 않는다. 현재 구현은 SciPy least_squares IK이며
PyRoKi/cuRobo를 호출하지 않는다.

실행 흐름
---------

* 기존 RGB ROI / 깊이 3D 박스로 대상을 선택하고 필터링된 ICP 포즈·이동 속도를 확보한다.
* 기준 파지, 물체 기준 yaw ±8도, 접근 위치 base X ±1.5cm의 다섯 후보를 만든다.
  yaw를 바꿔도 물체에 대한 파지점의 위치는 유지한다. 접근 오프셋은 합류 허용 거리 안이다.
* 후보마다 Approach → TrackGrasp(하강·닫힘) → Lift를 계획한다.
  기존 IK·관절 제한·속도·가속도·샘플 경로 충돌 검사와 Lift의 파지 물체 외곽 검사를 사용한다.
  동역학 제한으로 소요시간을 늘릴 때마다 이동 물체의 미래 포즈를 다시 계산한다.
* Lift까지 통과한 후보 중 점수가 가장 낮은 것을 선택한다.
  점수 = 오른팔 7관절의 경로 길이 합(rad) − 2 × min(최소 충돌 여유 / 0.4m, 1).
  손가락은 후보마다 동일하게 닫으며 점수의 관절 이동량에서 제외한다.
* 후보 비교는 즉시 실행할 궤적이 아니다. 비교 완료 후 최신 관측과 측정 관절을 다시 받아
  선택 후보의 전체 경로를 새로운 시작 시각으로 재검증한 뒤 Approach만 실행한다.
* 접근 완료 후 선택 후보 ID를 PlanMotion으로 전달한다. 다른 파지 자세로 바꾸지 않고
  최신 유효 관측으로 TrackGrasp와 Lift를 다시 검증한다.
  가림 중에는 기존 원본 측정 시각과 컨베이어 속도를 사용하는 제한된 예측을 유지한다.
* 닫힘 후에는 별도 파지 성공 확인 없이 측정 관절에서 Lift를 계획·실행한다.
  이후 스캔·적재·개방·후퇴 흐름은 유지한다. 적재 확인은 하지 않는다.

계산 중 취소·장면/시계 변화·관절 이동, 실행 시작 시각 누락은 계속 거부한다.
실행 중에는 기존 관절 추종 오차·ICP 예측 편차·관측 최신성·가림 불확실성 검사를 유지한다.
후보가 모두 거절되면 접근 궤적을 반환하지 않는다. 선택 후보의 최신 재검증이 실패해도
이전 궤적을 실행하지 않는다. 현재는 이 경우 작업 실패이며 다른 대상 자동 재선택은 하지 않는다.

시간과 메시지
-------------

후보 비교용 selection_start_lead_s=1.0은 비교용 예측 시각이며 실행 예약이 아니다.
실행용 start_lead는 SIM에서 0.4초에서 0.8초로 변경했다. 전체 경로 재검증 및
실행기의 재검사 시간을 확보하는 값이다. 접근·하강·닫힘 시간은 실제 계획의
retiming 결과로 결정하며 고정 7초 예측을 다시 도입하지 않았다.

PlanMotion.Goal 및 MotionPlan에 grasp_candidate_id를 추가했다.
Approach 응답의 ID를 BT가 보관하고 같은 작업의 TrackGrasp 요청에 전달한다.
새 작업 시작 시 ID를 초기화한다. 메시지 ABI 변경으로 모든 생산자/소비자의 재빌드가 필요하다.

/task/grasp_candidates(std_msgs/String JSON)는 후보별 통과/거절 단계·사유,
점수·여유·경로 미리보기·관측/계산/시작 시각을 발행한다. SIM trace가 원문을 기록한다.
BT 상태 사유에는 선택 후보와 Lift 사전 검증 여부가 표시된다.

검증과 한계
-----------

7개 Jazzy 패키지 빌드, 257개 테스트 통과. 추가 테스트는 Lift 실패 후보 제외,
모든 후보 실패 시 궤적 미반환, 점수의 이동량/충돌 여유 반영, retiming 예측 시각,
선택 자세 재사용 및 최신 타깃 반영을 검증한다.

실제 MuJoCo + YOLO/ByteTrack + 필터링 ICP 실행:

* 다섯 후보 모두 경로 검사 통과. approach_x_plus_15mm 선택.
* 비교 당시 기준 후보: 이동량 2.9007rad, 최소 여유 0.1616m, 점수 2.0928.
* 선택 후보: 이동량 2.8702rad, 최소 여유 0.1629m, 점수 2.0556.
* 비교 관측 6.256초 → 재검증 관측 7.786초. 재검증 후 접근 예약 8.858초.
* 접근 후 TrackGrasp/Lift 재검증. Lift 13.974초, ScanPose 16.864초,
  WaitBarcode 25.228초, Release 34.646초, 후퇴 완료 43.350초.
* 물리 경고0, 설비 침투0, weld0. 물체 접촉 침투 최대23.14mm는 남아 있다.

초기 두 실행은 계산/실행 검사 시간 때문에 시작 예약을 놓쳐 움직이기 전에 거부됐다.
최종 실행은 최신 관측 재검증과 0.8초 시작 여유를 적용했다.
단일 최종 시나리오이며 성공률·실기 성능·실제 스캐너 검증이 아니다.
다섯 후보 안에서의 선택이며 모든 IK 해/접근 방향을 탐색하지 않는다.
미리보기는 계획이며 이후 최신 관측/측정 관절에 따라 실행 경로는 달라질 수 있다.
기존 충돌 구·설비 박스 모델의 한계와 SIM용 카메라/설치 보정값은 그대로 남는다.

cuRobo 적용 판단
---------------

로컬 /home/xyz-ai/git/curobo는 cuRoboV2이며 v1과 API가 다르다.
다수 후보의 병렬 IK·충돌·경로 최적화는 다음 비교 대상이다. 현재 사용하진 않는다.
본 코드의 후보 생성/점수 모듈은 별도 grasp_candidates.py로 분리했다.
교체 전 같은 URDF·충돌 형상·관절 제한·타깃/시작 자세에서 통과율, 최종 여유,
워밍업 후 p50/p95 지연과 YOLO/ICP GPU 경합을 측정해야 한다.
